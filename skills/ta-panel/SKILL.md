# 모의 패널 (AI 페르소나)

실제 기술영향평가는 시민·전문가·관계 기관의 검토를 거친다. 이 스킬은 그 단계를 **예행연습**한다. 예행연습은 실제 참여가 아니고, 결과는 증거가 아니다. 이유와 근거 문헌은 `ta-panel` 에이전트 문서에 있다.

## 절차

1. **형식 고르기** — 리더에게 묻는다: 시민 패널 / 전문가 회의 / 관계 기관 의견 / 정책 담당자 워크숍. 그리고 검토할 초안(`02_impact.md` · `05_options.md` · `06_report.md`)
2. **페르소나 명세** — `templates/persona_spec.md` → `ta/07_panel_personas.md`. `ta-panel` 에이전트에게 실제 기준으로 짜게 한다
   - 시민: KISTEP 시민포럼 선발 기준(성별·연령·전공 균형) + 인공지능취약계층(「인공지능기본법 시행령」 제1조의2)
   - 전문가: 정부·NGO·학계·산업 균형, 기술·법·정책 전문성(GAO 전문가 회의)
   - 페르소나마다 그 집단의 실제 공개 입장 자료. 없으면 만들지 않음
3. **리더가 명세를 확인** — 빠진 집단, 고정관념으로 납작해진 묘사가 없는지 본다
4. **모의 검토** — `templates/panel_record.md` → `ta/07_panel_<형식>_YYMMDD.md`. 페르소나마다 질문·반론 → 사람에게 물어볼 질문으로 바꿈 → 빈 관점 모음
5. **반영** — 빈 관점은 정리관에게 '후보'로 넘긴다(출처 칸 `모의 패널 — 확인 필요`). 질문은 실제 검토자(다른 조·강의자)에게 가져간다

## 사람과 대조 (15·16주차)

- 발표 질의자를 이해관계자 역할(규제 기관·시민·산업·연구자)로 배정하고 질문을 받아 적는다
- 기록 3절에 사람과 AI가 같이 낸 질문 / AI만 낸 질문 / 사람만 낸 질문을 센다
- '사람만 낸 질문'이 무엇이었는지가 AI가 공중을 흉내 낼 때 놓치는 것을 보여 준다

## 규칙

- 기록 맨 위 "모의 검토(AI 페르소나) — 증거 아님"
- 실존 인물·기관의 이름으로 말하게 하지 않는다
- "시민 대부분은 …" 같은 비율·다수 표현을 쓰지 않는다
- 페르소나 의견을 합치지 않는다. 갈린 점은 갈린 대로
- 보고서에는 7.2 '모의 검토'에만 적는다
