# 범위 결정과 평가 질문

GAO 핸드북은 설계를 **범위 결정 → 초기 설계 → 설계 실행** 순으로 그리되, 실제로는 되돌아가며 고친다고 한다(GAO-21-347G p.12). 이 스킬은 범위 결정과 초기 설계를 한 장(평가 설계서)으로 끝낸다.

## 절차

1. **의뢰 확인** — `ta/00_request.md`가 없으면 리더에게 한 줄로 묻는다: "무엇을, 누구를 위해 평가하나요?" 답을 글자 그대로 `00_request.md`에 적는다
2. **템플릿 복사** — `templates/01_scope.md` → `ta/01_scope.md`(이미 있으면 덮어쓰지 않고 이어 쓴다)
3. **조사관에게 맡김** — `ta-scout` 에이전트에게 `00_request.md`와 `01_scope.md`를 주고 초기 상황 분석과 설계서 초안을 쓰게 한다. 같은 기술을 다른 기관이 이미 평가했는지 먼저 보게 한다(AI 에이전트라면 KISTEP 「2025년 기술영향평가」, GAO-25-108519)
4. **리더가 고를 것을 보인다** — 조사관이 낸 범위 선택지 2~3개와 장단점, 평가 질문 후보. 리더가 고르면 반영
5. **G1 게이트** — `../ta-orchestrator/references/gates.md`의 G1 기준으로
   - 기계 점검: `python3 ../ta-orchestrator/scripts/ta_check.py ta/ --gate G1`
   - 검수관 판정: `ta-reviewer`에게 G1과 `01_scope.md`를 준다
   - 판정서를 `ta/gates/G1_YYMMDD.md`로 저장
6. **리더 승인** — 보류면 [필수]만 고쳐 다시 판정. 진행이면 리더가 8절 승인 칸에 이름과 날짜를 쓴다

## 리더에게 보일 때

- 평가 질문 표와 범위 표만 먼저 보인다(설계 매트릭스는 파일 경로로)
- "질문에 의뢰자·대상 기술·영향 범위가 들어 있나", "무엇을 뺐고 왜 뺐나"를 함께 묻는다

## 하지 않는 것

- 범위를 에이전트가 확정하지 않는다
- 정책 목표를 특정 행동(규제·진흥)으로 미리 정하지 않는다
